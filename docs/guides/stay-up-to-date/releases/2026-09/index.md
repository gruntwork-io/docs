## pipelines-workflows


### [v4.29.0](https://github.com/gruntwork-io/pipelines-workflows/releases/tag/v4.29.0)

<p style={{marginTop: "-20px", marginBottom: "10px"}}>
  <small>Published: 9/24/2026 | <a href="https://github.com/gruntwork-io/pipelines-workflows/releases/tag/v4.29.0">Release notes</a></small>
</p>

<div style={{"overflow":"hidden","textOverflow":"ellipsis","display":"-webkit-box","WebkitLineClamp":10,"lineClamp":10,"WebkitBoxOrient":"vertical"}}>

  

Previously, the [`ignore_list`](https://docs.gruntwork.io/2.0/reference/pipelines/ignore-list) attribute only supported a comma-delimited list of globs as a string.

```hcl
repository &#x7B;
  deploy_branch_name = &quot;main&quot;

  ignore_list = &quot;README.md,.github/**&quot;
&#x7D;
```

As of this release, you can also use an HCL list to enumerate the globs you want Pipelines to ignore in your repository.

```hcl
repository &#x7B;
  deploy_branch_name = &quot;main&quot;

  ignore_list = [&quot;README.md&quot;, &quot;.github/**&quot;]
&#x7D;
```

As a consequence, you can also now use brace alternation to match on multiple paths in one glob when using the list form.

```hcl
repository &#x7B;
  deploy_branch_name = &quot;main&quot;

  ignore_list = [&quot;README.md&quot;, &quot;&#x7B;catalog, .github&#x7D;/**&quot;]
&#x7D;
```

For backwards compatibility, the existing comma-delimited string form is still supported.

**Full Changelog**: https://github.com/gruntwork-io/pipelines-workflows/compare/v4.28.0...v4.29.0

</div>


### [v4.28.0](https://github.com/gruntwork-io/pipelines-workflows/releases/tag/v4.28.0)

<p style={{marginTop: "-20px", marginBottom: "10px"}}>
  <small>Published: 9/21/2026 | <a href="https://github.com/gruntwork-io/pipelines-workflows/releases/tag/v4.28.0">Release notes</a></small>
</p>

<div style={{"overflow":"hidden","textOverflow":"ellipsis","display":"-webkit-box","WebkitLineClamp":10,"lineClamp":10,"WebkitBoxOrient":"vertical"}}>

  

Fixed a bug affecting access control pull requests in Enterprise Account Factory.

The initial IAM trust policies now use immutable OIDC subject claims from delegated repositories.


 Files read by stacks (e.g., by `mark_as_read` in a stack&apos;s `locals`) now trigger stack generation so that IaC changes can be detected.

Additionally, removing a file read by a stack will now trigger deletion protection if [`PIPELINES_FEATURE_VALIDATE_DAG_ON_DELETE`](https://docs.gruntwork.io/2.0/reference/pipelines/feature-flags#pipelines_feature_validate_dag_on_delete) is enabled.


Pipelines Hooks now receive a `PIPELINES_HOOK_CTX_API_VERSION` environment variable, initially set to `v1.0.0`. As more hook inputs are added over time, hook authors can check this variable against a minimum API version before their hooks attempt to run.

**Full Changelog**: https://github.com/gruntwork-io/pipelines-workflows/compare/v4.27.0...v4.28.0

</div>
